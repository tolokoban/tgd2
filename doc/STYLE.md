# `doc/` coding style

`doc/` is the documentation **and** the manual test application for `@tolokoban/tgd`. It is a React 19
SPA built with Rspack, written in TSX and MDX, and deployed to GitHub Pages
(https://tolokoban.github.io/tgd2). Every library feature should have a page here with a live demo.

## Tooling

- `npm start`: dev server (`rspack serve`). The library comes from `"@tolokoban/tgd": "file:.."`,
  so run `npm start` in `lib/` at the same time to rebuild it on change.
- `npm run generate`: runs **both generators**, and must be run after adding pages or demos:
  - `npm run routes`: `build-react-routes ./src/app/` regenerates `src/app/routes.ts` and `types.ts`.
  - `npm run demo`: `scripts/demo/index.ts` regenerates the `index.tsx` next to every `*.demo.tsx`.
- `npm run lint`: `oxlint src/`.
- Formatting: **Biome**, so **tabs**, double quotes. Most files end statements with semicolons; demos
  created from the template have none. Match the file you are editing.
- TypeScript strict, `jsx: react-jsx`, path alias **`@/*` → `src/*`**.

## Generated files: do not edit by hand

- `src/app/routes.ts`, `src/app/types.ts`: generated by `build-react-routes`.
- Every `index.tsx` that starts with `Warning! This code has been generated automatically.` and sits
  next to a `*.demo.tsx`. Edit the `.demo.tsx` and run `npm run demo`.
- `public/docs/`: the TypeDoc output from `lib/` (`npm run doc` in `lib/`).

## Routing (file-system based)

`src/app/` follows `build-react-routes` conventions (similar to the Next.js app router):

- `page.mdx` or `page.tsx` = a route. `layout.tsx` wraps all the routes below it. `loading.tsx`, `404.tsx`.
- `[value]/` = a route parameter.
- **Folders starting with `_` are not routes.** Put demos, components and assets for a page there
  (`_/`, `_bbox/`, `_background-with-depth/`).
- Links use hash routing: `[Back](#/articles/painter)`.

Main sections: `articles/` (one sub-folder per feature, with `articles/painter/<painter-name>/` for
painters), `tricks/` (recipes such as object picking), `tools/` (interactive tools: palette, glTF,
filter), `example/`, `quick-start/`, `api/`.

## Demos

A demo is a `xxx.demo.tsx` file whose default export is a React component that renders the shared
`View` from `@/components/demo/Tgd`. Two folder layouts exist, and both work:

```
articles/painter/bbox/
    page.mdx                     import Demo from "./_bbox"
    _bbox/bbox.demo.tsx          ← you write this
    _bbox/index.tsx              ← generated
```

```
tricks/object-picker/
    page.mdx                     import Demo from "./_/background.demo"
    _/background.demo/background.demo.tsx
    _/background.demo/index.tsx  ← generated
```

**The page must import the folder (its generated `index.tsx`), never the `.demo.tsx` file itself.**
The generated `index.tsx` wraps the demo with the code viewer and its "Show full code" button.
Importing `./_bbox/bbox.demo` renders the demo without any code.

The template (`@templates/demo`) is the reference skeleton:

```tsx
import { type TgdContext, TgdPainterClear } from "@tolokoban/tgd"
import View, { type Assets } from "@/components/demo/Tgd"
import SuzanneURL from "@/assets/mesh/suzanne.glb"

function init(context: TgdContext, assets: Assets) {
	// #begin Initializing WebGL
	context.add(new TgdPainterClear(context, { color: [0, 0, 0, 1], depth: 1 }))
	context.paint()
	// #end
}

export default function Demo() {
	return <View onReady={init} assets={{ glb: { suzanne: SuzanneURL } }} gizmo />
}
```

Rules:

- All the setup is in a top-level `function init(context: TgdContext, assets: Assets)`, never in
  React hooks. `init` may return a function `(settings) => void` to react to the `settings` sliders.
- **`// #begin <Title>` … `// #end`** (or `#region` / `#endregion`) delimit the code shown in the
  "focused" code view. Wrap only the meaningful Tgd code, and give regions a title when there are
  several.
- **Custom shaders in demos also use `TgdPainterProgram`**, with the GLSL inline in `vert.mainCode` /
  `frag.mainCode`, so readers see the whole demo in one file. (Older demos import `./xxx.vert` /
  `./xxx.frag` files, which the generator still adds to the code viewer. Don't do this in new demos.)
- Assets are imported as URLs (`@/assets/mesh/*.glb`, `.webp` images placed next to the demo) and
  loaded by `View` via the `assets` prop (`image`, `glb`, `data`, `text`). Read them as
  `assets.glb.suzanne`.
- Useful `View` props: `controller={{ inertiaOrbit: 2000, maxZoom: 100 }}` (adds an orbit camera
  controller), `gizmo`, `width`/`height`, `options` (WebGL context attributes), `settings`, `fullscreen`.
- End `init` with `context.paint()`. Frame the scene with `context.camera.fitSpaceAtTarget(w, h)`.
- Import everything from the public package `@tolokoban/tgd`, never from `lib/src`. The demo then
  also checks that the feature is exported.
- Demo code is shown to readers, so keep it short and readable, without abstractions.

## MDX pages

```mdx
import Demo from "./_bbox"

# [TgdPainterBBox](docs/classes/TgdPainterBBox.html)

<Demo />

Useful to debug a bounding box.

---

[Back](#/articles/painter)
```

- Title = the class name, linked to its TypeDoc page: `docs/classes/<Class>.html`,
  `docs/functions/<fn>.html`, `docs/interfaces/<Iface>.html`.
- `<Demo />` comes right after the title, followed by a short explanation. Code blocks use
  ` ```ts `, ` ```tsx ` or ` ```glsl `, optionally `showLineNumbers`.
- Pages are written in English (the README says the site was originally in French, and some old
  pages still are).
- **When adding a painter page, also add a bullet to `articles/painter/page.mdx`** (alphabetical,
  `- [Name](#/articles/painter/name): one-line description.`).

## React components (`src/components`)

- One folder per component in PascalCase: `Name/Name.tsx`, `Name/Name.module.css`, `Name/index.ts`
  (from `@templates/Component`). Some older folders are kebab-case (`code-editor`, `settings`).
- Function components, `React.useState` / `React.useRef` / `React.useCallback` written with the
  `React.` prefix. Props interfaces live next to the component.
- UI building blocks come from **`@tolokoban/ui`** (`ViewButton`, `Theme`, icons). State helpers come
  from `@tolokoban/react-state`, and type guards from `@tolokoban/type-guards`.
- Styles are CSS modules imported as `Style` / `styles` / `Styles`.

## Debug traces

`console.log("🐞 [file@line] …") // @FIXME: Remove this line written on <date>` lines are temporary
traces from the author's editor. They are tolerated while a demo is being built. Mention them when
you see them, but do not remove them unless asked.
